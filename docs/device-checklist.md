# Android 実機での受け入れ確認

自動テストは業務ロジックと通知ポートを検証する。OSが実際に通知すること、画面の表示、タップ操作は別途実機で確認する。

1. APKをインストールし、起動する。5タブが表示されること。
2. 空のホームから課題を追加。授業、課題名、日付・時刻を指定して保存する。
3. 課題詳細で日付と時刻、残り時間、授業、未着手が表示されること。
4. メモ、推定作業時間、重要度を編集し、作業中→完了→提出済み→未提出と変更する。
5. アプリを終了して再起動。保存した課題、設定、授業が維持されること。
6. 機内モードで課題一覧・詳細・TODO・カレンダーを表示し、課題を編集できること。
7. 「今日やるべきことに追加」で遠い締切の課題が前者へ移ること。提出済みにするとTODOから消えること。
8. 締切を翌日の23:59に設定し、24時間以上残っていても「今日やるべきこと」へ自動分類されること。明後日へ変更すると「余裕があるもの」へ移ること。
9. 月末・年末を含むカレンダーを移動し、該当日の締切数と詳細への遷移を確認する。
10. 一覧の4種類のソートと4種類のフィルターを確認する。
11. 課題URLを設定して端末ブラウザが開くこと。URLがない場合もクラッシュしないこと。
12. 設定から通知を許可する。Android 13以降ではOSダイアログを確認する。
13. 締切を現在から**3時間2分後**に設定し、「3時間前」をONにする。アプリをバックグラウンドにして約2分後の通知を確認する。OSによって遅延する場合は省電力設定も確認する。
14. 通知をタップすると該当の課題詳細が開くこと。アプリ終了中からも確認する。
15. 同じテスト用課題を通知前に提出済みに変更。旧時刻に通知されないこと。
16. 未提出に戻して新しい未来の締切を設定し、通知が再予約されること。
17. 締切を変更した場合に旧時刻で通知されず、新時刻で通知されること。
18. 課題削除・該当設定OFFの場合も旧予約が届かないこと。
19. 端末側で通知権限を拒否し、課題登録が可能でホーム・設定に案内が表示されること。再許可後、通知を再設定する。
20. 端末を再起動し、未提出の予約が維持されること。
21. 文字サイズを拡大した端末、小型端末、キーボード表示時に保存ボタンまでスクロールできること。

## manaba連携

開発ビルドまたはAPKと、利用を許可されたテスト用アカウントで確認する。実ユーザーのID、パスワード、Cookie、認証画面は記録しない。

1. 設定に大学指定のhttps manaba URLを入力し、「manabaにログイン」を押す。
2. 大学のログインをWebView内で完了する。manabaと同じoriginへ戻るまで「ログインして同期」が成功しないこと。
3. ログイン後画面で「ログインして同期」を押し、初回同期後に設定が「manaba連携済み」になること。
4. アプリを通常終了して再起動し、「ログイン状態を確認」でパスワードの再入力なしにログイン後画面が開くこと。サーバーがセッションCookieを終了時Cookieとして発行する場合は再ログインになることも記録する。
5. manaba側でセッションを失効させてから「ログイン状態を確認」を押し、ログイン画面へ戻った場合に期限切れメッセージが表示され、自動リトライしないこと。
6. 機内モードでネットワークエラー、テスト環境でHTTP 503を返せる場合はメンテナンス表示を確認する。Cookieやフォーム値が画面・Metroログへ出ないこと。
7. 「ログアウト / 連携解除」で「課題を残す」を選び、次にログイン画面を開いた際に再認証が必要なこと。
8. テスト用manaba課題をローカルに用意できる場合、「課題も削除」でmanaba課題だけが消え、手入力課題は残ること。
9. 大妻女子大学のテスト用manabaでログイン後、小テスト・アンケート・レポート・プロジェクトの課題名、授業名、締切、提出状態が同期されること。
10. 同じ課題を再同期して重複しないこと。manaba側で締切を変更して再同期すると、ローカルのメモ・重要度を残したまま締切だけ更新されること。
11. 締切表示がない項目や解析できない項目は件数を表示してスキップし、既存データを削除しないこと。

通知の精度はAndroidの省電力・メーカー実装に依存する。アプリの強制停止はOSが通知を止める場合があり、通常のバックグラウンド移行と区別して検証する。
