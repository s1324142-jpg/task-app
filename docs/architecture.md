# Version 0.1 の設計

## 責務

- `src/screens`：5タブ、課題詳細、登録・編集。React NativeのネイティブUI。
- `src/ui`：色、共通カード、ボタン。将来のテーマ切替はこの層で対応。
- `src/domain`：Assignment / Course、日付、優先順位、通知候補。React Nativeに依存しない。
- `src/data`：AsyncStorageに1つのJSONスナップショットを保存。バージョン・型・関連付けを検証。
- `src/services/controller.ts`：変更を直列化し、保存完了後に画面と通知を更新。
- `src/services/notificationReconciler.ts`：実機APIから独立した通知予約の差分更新。
- `src/services/notifications.ts`：Expo Notificationsの権限・Androidチャネル・日時予約。
- `src/providers`：将来の外部課題取得と、手動編集を保持したマージ。

## 保存と通知の順序

1. ユーザー操作をキューに追加。
2. 最新スナップショットから次のデータを計算し、検証。
3. 端末内へ保存。失敗した場合は画面を更新せず、操作を再試行可能にする。
4. 画面に保存内容を反映。
5. OSの予約一覧と、保存データから算出した通知候補を照合。
6. 削除・提出済み・締切変更・設定OFFで不要になった予約を取消し、必要分のみ追加。

予約のIDは課題IDと通知種別から生成する。日時・タイトル・本文が一致する予約はそのまま使用する。途中終了後も、次回起動・フォアグラウンド復帰・手動再設定で保存データに合わせて修復する。通知更新が失敗しても課題保存は維持し、ホームと設定に警告を表示する。

AsyncStorageとOS通知は同一トランザクションにはできない。保存直後の強制終了やOS APIの失敗から次回再設定まで、古い予約が残る可能性がある。通常成功経路では提出済みへの変更完了までに予約取消しを待つ。実行中に届く提出済み通知も表示を抑制する。

Androidは直近500件、将来のiOSは直近60件までを予約し、超過時は明示する。上限後の通知はアプリの次回起動・復帰時に補充する。端末により省電力制限やOSの上限が異なるため、実機で確認する。

## 日付と優先順位

- 保存日時はISO 8601。手動登録はUTCへ変換し、表示は端末タイムゾーン。
- 今日・明日などの分類は現地の暦日。今週は月曜0時〜翌月曜0時。
- 「3日以内」「7日以内」のホーム分類は、それぞれ2〜3日後・4〜7日後で重複なし。今日の締切超過は今日締切にも含む。
- 相対時間と優先順位は30秒ごと、およびアプリ復帰時に更新。
- TODOは未提出課題を「今日やるべきこと」と「余裕があるもの」に分ける。手動指定または現地日付で提出期限が明日までの課題を前者へ自動分類し、それ以外を後者へ置く。各分類内は高スコア順、同点なら締切順。
- 完了は未提出として管理。完了時は推定作業時間による加点を外す。
- 日単位の通知は現地9時、早朝締切の当日通知は0時。3時間前は正確な差分で候補を生成。過去時刻は予約しない。

## manaba連携の境界

`ManabaAuthService`と`ManabaProvider`を分離する。認証はネイティブWebViewで大学の指定URLを開き、ID・パスワード・SSO・多要素認証の入力は大学またはIdPのページ内でユーザー自身が行う。アプリへ渡すページ情報は現在URL、タイトル、一般的なパスワード欄の有無だけであり、Cookie、フォーム値、本文はJavaScriptへ取り出さない。

接続メタデータはSecureStoreへ保存する。認証CookieはWebView/OSのCookieストアに保持し、AsyncStorageやアプリ独自形式へ複製しない。Androidではログイン完了時にCookieストアをflushする。連携解除時はアプリのWebView Cookieストアを消去してからSecureStoreのメタデータを削除する。現時点ではmanabaが唯一のWeb認証連携なので全Cookieストアを対象にする。別LMSを追加するときはCookieストアまたはWebView profileの分離が必要になる。

ログイン完了は、入力したmanaba URLと同じoriginへ戻ったこと、パスワード入力欄がないこと、ユーザーが表示内容を確認して完了操作をしたことを組み合わせて判定する。同期開始時に同じWebViewセッションを使い、ログインフォームへ戻った場合は期限切れにする。リトライは自動実行しない。

特定大学のURLは初期登録せず、利用者が大学指定のmanaba URLを設定する。ログイン済みWebViewから同一originの標準提出物集約ページだけを`fetch`する。小テスト・アンケート・レポート・プロジェクトのリンクをDOM上で解析し、授業名、課題種別、課題名、締切、提出状態、課題URL、外部IDだけをReact Native側へ渡す。生のHTML、フォーム入力値、Cookieはメッセージや永続ストレージへ渡さない。受信値はZodで件数・長さ・型を制限し、締切は日本時間を明示したISO日時へ変換する。

マージはexternalId優先、なければ授業名とURLを使用する。締切を識別子に含めないため、締切変更で重複しない。識別情報や必須情報が欠けたレコードはスキップ件数として返す。安定した課題IDもURLもない場合、タイトルと締切で不確かな同一判定をしない。取得側はセッション情報を含まない恒久URLを渡す責務を持つ。

取得データの保存は、WebViewから`ok`の取得結果を受信した場合だけ`AppController.mutate`経由で行う。これによりFirestore同期と締切変更時の通知再予約が既存の経路で動き、認証切れ・通信失敗・解析失敗では前回データを上書きしない。セッション切れではSecureStore上の状態だけを`expired`にし、再ログイン後にホームまたは設定の手動同期ボタンから再取得する。HTML構造変更の自動判定とバックグラウンド同期は未実装。
